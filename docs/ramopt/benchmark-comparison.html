NuExpansionHunter: streaming memory comparison

Baseline: main at f3b1256. Candidate: exact index compression, on-demand queues and earlier streaming cleanup. The primary scope is coordinate-sorted BAM, streaming, and a prepared catalog cache. All tests retain VCF, JSON and BAM output. Only BAM record order may differ; complete fields and duplicate multiplicity are compared. Additional sequence-preprocessing workers are zero in all configurations. Counts below are compute / HTS decode / BAM encode workers, not CPU-core limits.

Total time includes process startup, index loading or construction, read processing, genotyping, output, and exit. Cache preparation is separate. Time and peak RAM are medians across measured runs. RAM is in MiB; maximum observed process peak RSS is retained below. Changes use the median of paired ratios; negative means lower and can differ from the ratio of the two marginal medians.

Changes are green/red only when the 95% bootstrap interval is entirely below/above parity. Intervals crossing parity use plain text and are inconclusive.

These are local macOS ARM64 synthetic stress tests. Sub-second runs and intervals based on only three pairs require caution. An interval crossing parity cannot establish speedup or regression and does not guarantee no regression. covered10k is approximately 8x LowDepth; genotyped10k additionally checks actual Genotype fields. Existing unsorted results are supplementary and outside the user's primary acceptance scope. Small catalogs, long reads, distant mates and other cases do not necessarily achieve 50% lower memory.
