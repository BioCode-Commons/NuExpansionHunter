Decision: retain v1, which has completed whole-application validation, and do not integrate any isolated tuning variant in this round.

Scope: all tuning code, build artifacts and evidence remain under work/index-tuning.
Product KmerIndex.cpp / KmerIndex.hh unchanged: True.
The original v1, extreme-test and application performance evidence is retained in full.
The final acceptance scope is sorted BAM + streaming + prepared cache.

Prepared and screened variants: frozen, count16, count32, prefix2, prefix3, combined2, combined3, entrylite, combined3lite.
count16 caches a uint16 count in existing PathView padding, using the 65535 sentinel to fall back to the full 32-bit count; the object remains 16 bytes.
count32 caches the complete 32-bit count; prefix2/3 combine prefix-directory loads and use fixed-width scalar comparisons for small buckets; entrylite removes unused key loads and forces inlining.

Correctness: all 9 isolated versions pass the 18 extreme profiles, complete output/path audits for 32 mixed loci, and API comparisons.
API comparisons cover >65535 paths, default/missing/membership-only/out-of-range behavior and exception text; all match original exactly.
v1 also passes 18/18 extreme ASan/UBSan profiles, with complete stdout matching the earlier audit. Only KmerIndex.cpp and the probe are instrumented; supporting libraries use Release builds, and LeakSanitizer is disabled.

Reasons for not integrating:
1. prefix2/3 and their combinations substantially hurt prefix hits and ordinary mixed path queries; they were not pursued further.
2. count32 improves some fallback cases but hurts ordinary mixed path queries; it was not pursued further.
3. count16 passes the final fresh three-way comparison and improves some fallback cases, but adds no memory benefit and does not eliminate the single-index hot-hit tradeoff.
4. count16 is approximately equal to v1 for ordinary rolling path retrieval. Replacing v1 for a local improvement would invalidate the applicability of evidence from the 44 whole-application configurations already completed at the time of this decision. No additional tuning or integration is included in this round.

Final count16 validation: 31 cases (23 extreme + 8 mixed), with alternating original/frozen/count16 order for each case, 1 warmup and 5 measured rounds; the fastest sample is calibrated to approximately 0.15 seconds.
All timed stdout checksums match. The following values are medians of per-round ratios, not ratios of marginal median times; >1 means slower.
