NuExpansionHunter Jiapeng-OPT 实现优化验证报告

本轮实现并筛选四项候选，最终仅保留 candidate1（反向互补方向查询减少重复工作）和 candidate4 v2（只计算当前 target 用到的打分 profile）。两项均有通过门槛的局部收益，candidate2 和 candidate3 两版已排除。最终组合的所有端到端结果文件逐字节一致，峰值 RAM 的中位数和最大值均通过预设波动范围检查。端到端耗时观察与局部收益分开报告；不能由本次合成数据验证推断真实 WGS、其他平台或任意输入的保证。

固定基线为 Jiapeng-OPT 的 9b29510b63ddf39256f2649a1ca0b408b4fd6af9，baseline executable SHA256 为 fb276692b38c5b5991dbc9cfdc86958232ab23f65438e447115835209c077d04。当前组合 executable SHA256 为 ef76e52bc9a99c7e8c16c9086a8a4f163d1cef7619a49291113a8ab1671192fd。该哈希与最终端到端计时所用程序一致。

测试在 macOS arm64、Apple clang 21.0.0、CMake 3.31.6 上进行。正式程序统一采用 Release、-O3 -DNDEBUG -std=gnu++11，以及 -Wno-error=deprecated-literal-operator -Wno-error=deprecated-declarations 两项诊断兼容参数。Boost 1.73、HTSlib 1.10.2 加仓库补丁、spdlog 1.6.1、GoogleTest 1.10、abseil 20210324.2 和 xz 5.4.6 在 baseline/candidate 间保持一致。probe 的实际 flags 单独保存在构建记录，不能把正式程序全部 flags 原样归给 probe。

四项候选的最终实现与筛选：

1. Candidate1：方向预测中避免构造反向互补临时字符串，将反向遍历、互补转换与 rolling k-mer 统计融合，同时保留大小写、非标准碱基、nonoverlapping match 计数及 forward 优先的 tie 规则。mixed、reverse、invalid、long 和加长计时的 short-confirm 均通过；forward 分支没有证明加速，也没有足够证据证明退化。
2. Candidate2：PinnedDagAligner 的 suffix 查询视图方案正确性检查通过，但 mixed 基本无变化，branch 不到 2% 且耗时不足 0.5 秒，short 观察更慢。因此拒绝，不因减少字符串复制就推定它更快。
3. Candidate3 v1：省去 DP interior 的冗余初始化。long 获益，但 dense 9/9 更慢，约 +2.10%，故没有通过跨场景筛选。v2 将优化限制为每行恰有一个合法、已完成前驱的图，其余恢复原初始化/分配次序；五个 workload 仍均变慢约 6.04%–14.44%，因此两版全部拒绝。不能把 v1 的 long 结果当作 v2 或最终组合的收益。
4. Candidate4：仅预计算当前 target 使用到的字符 profile。初版跳过 absent profile resize，会改变 vector 几何扩容历史、可能增加保留容量；v2 保留所有 profile 原有 resize/capacity 历史，仅跳过无用的分数计算。typical、short、join 通过；long 约 1.58% 未达 2%；全简并字符场景观察到约 0.22% 小幅退化，应保留此负向结果，不能声称所有 DP 输入均加速。最终使用 v2。

每个正式 workload 先运行 1 个 warmup pair，然后 9 个独立进程 pair，交替先后顺序；正式计时期间没有并发编译/测试/其他基准。计时为进程启动至退出的 wall time，比较文件在计时后读取。未清空系统 page cache，结果仅对应本地预热协议。

时间准入：配对 candidate/baseline wall ratio 的中位数 <0.98；10,000 次固定种子 bootstrap 的 95% 区间上界 <1；双方运行时间中位数均 >=0.5 秒；同时检查其他代表性场景。表中“耗时减少”是 1 减配对比值中位数，不是两个耗时中位数相除。

RAM 记录 macOS wait4 的每进程 peak ru_maxrss（bytes）。每轮 peak 的中位数和全部轮次最大 peak 均必须不超过其对应 baseline 值加 max(256 KiB, 1%)；两个 gate 分别记录。这是明确噪声带内的经验判断，不等于证明所有输入绝不增加一字节 RAM。不能把略有正向 RSS 差值写成“完全不变”，也不能用 RSS 代替 PSS/USS 或多样本整机占用。

正确性与测试范围：

- 最终字符串 probe 与基线在 10,900 个方向预测案例和 516 个 suffix 案例上一致。
- 独立 DP v2 probe 在 1,052,788 个案例上对完整矩阵/traceback等可观察输出逐字节比较，canonical stream 为397,363,521 bytes，一致；不是只比较checksum。该测试运行在独立 baseline/candidate3-v2/candidate4-v2 probe 上。
- final-source-binding.json 确认最终 DP 源文件与已测试 candidate4 v2 一致，Details.hh/PinnedDagAligner.hh 回到 baseline。这个源码哈希绑定不是重新对最终组合运行百万案例；不能将二者混写。
- 最终 ctest：EH 126 tests 中125通过，唯一失败与原基线相同；GraphTools 30/30 test programs通过。原基线为EH124/125通过。失败是 PreparedCatalog.WholeCatalogRoundTripAndIndependentHandleLifetime 中 graph JSON 的 edge labels [b,a] 与 [a,b] 顺序差异，不能写“全部单测通过”。
- ASan保留默认容器检测时，独立baseline/candidate3-v2/candidate4-v2均在原有computeAlignPenalties查询padding访问处触发container-overflow（逻辑size之外、capacity之内）。未混入本轮性能patch修复。
- 后续隔离测试用 ASAN_OPTIONS=detect_leaks=0:detect_container_overflow=0，4,212 cases完成且无额外ASan/UBSan诊断；明确排除了容器逻辑越界与泄漏检查。这不是默认sanitizer全通过，也不是最终完整程序的全流程sanitizer验收。

端到端输入仅来自仓库synthetic example，以及把同一坐标locus定义复制32份的dense32。用户没有提供真实数据；dense32不是WGS、32个样本或32倍覆盖率，不能据此宣称真实WGS/多样本吞吐收益。记录实际threads、modes和cache设置；当前这些运行是单计算线程，encode同步，streaming decode同步。其他平台、数据、线程数未验证。

端到端比较要求VCF、JSON、压缩BAM文件所有字节相同，包含BAM顺序、header、记录、标签和重复次数，未做排序或标准化；采用SHA256加完整分块字节比较。程序stdout/日志含运行时间戳，可能出现stdout_identical=false；结果文件是否相同以outputs_identical为准，原日志不改写。每轮预先仅移除该轮三个指定旧结果，避免残留文件误通过。

单项candidate1和candidate4的example/dense32、seeking/streaming smoke结果文件均一致。这些单pair仅验证正确性，不用于正式提速结论。candidate4 dense32 streaming的首次单pair RSS +294,912bytes，曾超256KiB门槛；后续独立9pair确认的median/max RSS均比baseline少65,536bytes，两项RAM gate通过。确认实验配对耗时比0.995781，95%区间[0.984099,1.008661]，未证明端到端加速；保留首次负向观察，不能用后续实验删除它。
